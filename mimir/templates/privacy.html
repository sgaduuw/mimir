In short

  • No accounts, no analytics, no tracking pixels, no advertising.
  • Three strictly necessary Cloudflare cookies and two local preferences (theme and thread fold).
  • Request logs are kept for two days, for abuse triage and debugging.
  • Questions or requests: the privacy contact address.
{{ heading('controller') }}

{{ site_name }} is a personal project run by Eelco Wesemann (Netherlands). Privacy enquiries: ratatoskr@init1.nl.

{{ heading('what-it-is') }}

A read-only web archive of public-inbox kernel mailing-list mirrors (lkml and related). There are no accounts. Every message displayed is already-public material from lore.kernel.org and the other public-inbox mirrors; {{ site_name }} does not introduce any new disclosure.

{{ heading('browser-storage') }}

Three Cloudflare cookies, set by the edge for security and availability:

NameSet byPurpose
__cf_bmCloudflarebot mitigation
cf_use_obCloudflareorigin-failover, the Cloudflare “Always Online” feature

All three are strictly necessary for operating the service. Under the ePrivacy Directive (Art. 5(3)(b)) and EDPB guidance, strictly necessary cookies do not require consent. Cloudflare’s published cookie list documents them.

Local storage preferences, set by {{ site_name }} itself:

NameSet byPurpose
mimir.theme{{ site_name }}your light or dark theme preference. Written when you choose Light or Dark; choosing System removes it. Stays in your browser, never sent to the server.
mimir.fold.<id>{{ site_name }}your fold-state preference for that thread’s reply tree. Written only when you click the fold toggle. Stays in your browser, never sent to the server.

Page navigation does not store copies of pages in local or session storage. Back and forward navigation reload pages from the server.

No analytics. No tracking pixels. No advertising. No third-party embeds beyond the static-asset CDNs listed below.

{{ heading('server-side') }}

Standard HTTP request metadata, one log record per request:

  • the time, a request ID, and how long the response took;
  • your IP address;
  • the request method and path, the response status, and the response size;
  • your browser’s User-Agent, and the browser hints that Chromium-based browsers send with it (browser brand and version, mobile or not, operating system);
  • the page you came from (Referer);
  • the request-context headers browsers add (Sec-Fetch-*, Purpose, Sec-Purpose, HX-Request) and the content types and languages your browser accepts (Accept, Accept-Language);
  • your country, when Cloudflare supplies it.

Retained in operator-side logs for two days, then deleted. Used for abuse triage and debugging.

Legal basis: legitimate interest (GDPR Art. 6(1)(f)) in operating and securing the service.

{{ heading('third-parties') }}
  • Cloudflare (US) fronts {{ site_name }} as an edge proxy and bot-mitigation layer. It sees your IP and request metadata. Cloudflare’s Data Processing Addendum and the EU Standard Contractual Clauses cover the EU-to-US transfer.
  • jsdelivr.net and unpkg.com serve the two vendored frontend assets (Pico CSS, htmx). Visiting their CDNs reveals your IP to them. Both files are integrity-pinned (SRI), so their content cannot change without breaking the page.
  • GitHub Container Registry hosts the deployment image. Not visitor-facing.
{{ heading('redaction') }}

Visible HTML on message pages, and their Markdown versions, redact non-allowlisted sender addresses to <hidden> and DCO-trailer addresses to <redacted>. This is a friction layer, not a privacy guarantee. The same bytes are public via lore.kernel.org and every other public-inbox mirror; a determined scraper can fetch the original RFC 5322 message in a single HTTP call. The redaction aims to make casual scraping less rewarding, not to claim that {{ site_name }} hides the addresses.
